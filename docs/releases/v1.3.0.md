# Easnap v1.3.0

v1.3 opens **your own video files in the trim view**: pick a video from the
tray menu, from Explorer's "Open with" or from the command line, cut the part
you want and save or copy it as MP4 or GIF. The original file is never
changed. It also closes the open findings of the November audit: copying and
saving a tall Scrollshot no longer freezes the window, editing a tall image
is faster, a recording started on a still desktop uses the fast capture path,
and settings that cannot be saved say so. These notes cover everything that
changed since v1.2.0.

## New

- **Open a video in the trim view.**
  - **Tray menu, "Open video...":** a file dialog, then the trim view with the
    video, the same one a recording ends in: set In and Out, play the part,
    then **Save** or **Copy** as MP4 or GIF.
  - **Explorer, "Open with":** the installer adds Easnap to the "Open with"
    list of `.mp4`, `.m4v`, `.mov`, `.wmv`, `.asf` and `.avi` files for the
    current user. It does not make Easnap the default program for any of
    them. A file opened this way while Easnap is already running is handed
    to the running Easnap. The portable ZIP adds no entries.
  - **Command line:** `Easnap.exe <file>` or `Easnap.exe --open <file>`.
  - **What opens:** MPEG-4 files (`.mp4`, `.m4v`, `.mov`) with H.264,
    MPEG-4 Part 2 or Motion JPEG video and AAC, MP3 or PCM sound; Windows
    Media files (`.wmv`, `.asf`) with WMV or VC-1 video and WMA sound; and
    `.avi` files with the same video and sound kinds as MPEG-4. Sound is
    optional. A file that Easnap cannot open is refused with one message
    that says why: not a video, damaged, a kind of video Easnap does not
    handle, protected, no picture, too large for MP4 (GIF is still offered),
    on a network or offline drive, in use by another program, or a format
    that needs a Windows codec extension.
  - **Your file is safe.** Easnap reads the file and never writes to it,
    moves it or deletes it. Save refuses the file's own name and location, in
    any spelling, so the original cannot be written over. The trim view's
    title shows the file name, and Close returns to the tray without a
    question unless an export is running.

## Changed

- **Copying and saving a tall Scrollshot** no longer freezes the window. The
  image is encoded in the background while the tools show "Copying…" or
  "Saving…" and stay responsive; a cancelled or failed export says so.
- **Editing a tall image** is faster: moving a shape, a spotlight or a
  pixelating brush repaints only what changed, so a drag follows the pointer
  at any image height.
- **A recording that starts on a still desktop** now uses the fast capture
  path (Desktop Duplication) instead of staying on the slower GDI path for
  its whole length.
- **The trim window** is a little wider at its smallest size, so every button
  caption fits in both languages.
- **Settings that cannot be saved** (a full disk, a read-only file) are
  reported once per run in a notification; the change still applies while
  Easnap runs.
- **A crash report that cannot be written** leaves a log line that says which
  step failed and why, and the dump is tried again before giving up.

## Fixed

- A screenshot taken while the capture workspace was on screen could differ
  from the screen by one level at a few colour values. The shading is now
  split around the frame, as Scrollshot does, and the values match.
- A cancelled spotlight preview left the rest of the picture darkened on
  screen until the next repaint.
- A pixelating brush drawn upward or to the left showed old blocks until the
  button was released.
- After a change to "Start with Windows" that could not be saved, the message
  said "The other settings were saved" even when they were not.
- In the trim preview, a quick Play, Pause and Play right after the preview
  stopped at Out could resume at the old pause point and stop again at once
  (seen once in thirty test runs). The preview now checks the player's clock
  against the requested position for three seconds after it resumes and
  seeks again when the player did not follow.

## Under the hood

- The trim flow moved out of the capture coordinator into its own part with
  its own test ([ADR-039](../decisions/ADR-039-coordinator-trim-flow.md));
  recording stays in the coordinator.
- Recording reuses its frame pictures instead of allocating one per frame
  ([ADR-042](../decisions/ADR-042-recording-frame-buffer-cost.md)): page
  faults per frame fell from about 2,160 to 860 in the lab.
- A realistic Scrollshot test application (text, pictures, a fixed header,
  content that loads late) checks the stitched image pixel by pixel
  ([ADR-041](../decisions/ADR-041-scrollshot-realistic-test-application.md)).
- Long functions in the audio pipeline and the editor were split without a
  change in behaviour; the documentation was tidied.

## Upgrading from v1.2.0

- v1.3.0 installs over v1.2.0 as the same program and keeps its settings.
  Exit Easnap before you install.
- Nothing in the settings file changes. The installer adds "Open with"
  entries under the current user's registry key and removes them on
  uninstall.

Smart App Control turned on, Windows can block them.

To check a download:

```powershell
Get-FileHash .\Easnap-v1.3.0-windows-x64-setup.exe -Algorithm SHA256
gh attestation verify .\Easnap-v1.3.0-windows-x64-setup.exe --repo vseprr/easnap
```

Exit Easnap before installing over, or replacing, an existing copy.

## Validation

- **In the test lab,** a virtual machine with Windows 10 22H2, no GPU and a
  125 % display: the Full set (66 tests) after every change and the long
  repeats (74 tests) after the last ones. On the sources of this version the
  Full set passed 66 of 66 without a retry and the long repeats 74 of 74 with
  two retries, both on checks that were known before: the pointer landing on
  the trim window's caption, and a Scrollshot test fed pictures torn between
  two screen updates (see Known issues). Every capture test ran on Desktop
  Duplication or Windows Graphics Capture; none fell back to GDI.
- **By the owner,** on the development PC with two displays at 125 %, on a
  build of the branch: copying and saving a very tall Scrollshot, editing a
  tall image, settings with an unwritable settings file, the trim window at
  its smallest size, a recording started on a still desktop, and the video
  feature end to end (tray entry, "Open with" with Easnap running and not
  running, a refused file and its message, Close and Exit during an export,
  Save and Copy as MP4 and GIF, the original file untouched). No problem
  was found. The packaged installer of this version was not installed by
  the owner before publication; the Release workflow built, tested and
  checked the packages on a hosted runner.
- Not checked: videos with a Windows codec extension (HEVC), files on a
  network drive, Windows 11 and an N edition. The
  [validation records](validation-history.md#validation-of-v130) list the
  runs, and [project status](../project-status.md#not-validated) what has
  not been checked.

## Known issues

- Scrollshot can stitch a picture wrongly when one captured frame contains
  parts of two screen updates (the page scrolled while the frame was read):
  the stitched image then shifts by a constant and comes out too tall. Seen
  in the lab; the engine change is the next slice.
- Scrollshot in pages that scroll by fractions of a pixel (some browsers)
  can drift by up to three rows over a long page.
- In a very tall image the first frame of a spotlight preview takes 50 to
  200 ms, and a blur or pixelation that covers a tall area repaints slowly
  while it is dragged.
- Transient redraw artifacts can occur while resizing or maximizing the Trim
  window.
- Pins are captured like any other window; there is no option yet to keep
  them out of screenshots and recordings.

See [troubleshooting](../troubleshooting.md) for the questions that come up
most often.
