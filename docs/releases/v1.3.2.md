# Easnap v1.3.2

A maintenance release with nothing new to see. The code behind Easnap was
reorganized so that later corrections and features touch fewer places and
are safer to make. The windows, the text, the shortcuts, the settings file
and the pictures and recordings Easnap writes are the same as in v1.3.1.

## Changed

- **Internal restructuring.** The program's code is now arranged so that a
  colour, an icon, a button, an editor tool, a shortcut or a message is
  changed in one named place, and the layers of the code are checked
  automatically. The screenshot editor, the shared controls, the
  notification-area menu, the window plumbing and the audio and preview
  threads were split into smaller parts without changing what they do. The
  decisions are recorded in
  [ADR-043](../decisions/ADR-043-structure-for-cheap-changes.md).
- **Two small details behave differently,** both checked:
  - At a fractional display scale, a click on the very edge of a greyed-out
    button in the tools island could select an item of the property island
    instead. Such a click now does nothing.
  - When the display layout changes, Easnap now reads the monitor layout
    every time instead of only in some cases. Nothing visible changes.

## Upgrading from v1.3.1

- v1.3.2 installs over v1.3.1 as the same program and keeps its settings.
  Exit Easnap before you install.
- Nothing in the settings file or the registry entries changes.

| `*.sha256` | SHA-256 checksum for each file |

Both packages contain the same two executables. Easnap needs Windows 10
version 2004 or later, x64. The binaries and the installer are **unsigned**,
so Windows may display a publisher or reputation warning; on Windows 11 with
Smart App Control turned on, Windows can block them.

To check a download:

```powershell
Get-FileHash .\Easnap-v1.3.2-windows-x64-setup.exe -Algorithm SHA256
gh attestation verify .\Easnap-v1.3.2-windows-x64-setup.exe --repo vseprr/easnap
```

Exit Easnap before installing over, or replacing, an existing copy.

## Validation

- **By the owner,** on the development PC: the running program after the
  restructuring, with no problem found.
- **In the test lab,** a virtual machine with Windows 10 22H2, no GPU and a
  125 % display: the Full set passed 69 of 69 on the sources of this
  version, every audio, recording and preview test among them.
  `island_capture_exclusion` passed on its retry: its first attempt saw
  pixels where Windows shows notifications, a known effect of the lab
  machine, not of Easnap.
- **New checks** guard what the restructuring must not change: the pixels of
  every shared button and icon face in both themes (602 cases), the drawing
  of every kind of annotation and of text, and the coordinator's decisions
  (169 checks). Static analysis with clang-tidy found nothing.
- Not checked: the notification-area menu, Settings and About by automation
  (no test drives them; the owner used them), Windows 11, an IME. The
  [validation records](validation-history.md#validation-of-v132) list the
  runs.
