# Easnap v1.0.1

A maintenance release: no new features. It fixes defects found in a review of
v1.0.0, hardens the application and its packaging, and adds a one-file
installer.

## Fixed

- **Recording**
  - Losing an audio device during a recording is now detected. A failed read
    was mistaken for an empty buffer, so the recording continued silently.
  - Pause, Stop and closing could wait forever if video stopped advancing
    while audio was being recorded. The recording now fails after ten seconds
    without video progress instead of blocking.
  - A recording whose region left the desktop (monitor disconnected or
    resolution reduced) ends and opens for trimming, instead of repeating its
    last frame until stopped.
  - Recording dark content no longer switches capture to a slower path for the
    rest of the recording.
  - A failure recorded while pausing is no longer overwritten by the paused state.
- **Screenshot editor**
  - Fixed a crash when typing in the watermark field after pressing Esc, and
    when pressing Delete or undo while dragging an annotation.
  - Changing the font size while editing text no longer splits the edit into
    one undo step per keystroke, and Esc discards the text again.
  - The context controls keep their font when the window moves to a display
    with a different scale.
  - Saving over an existing file keeps that file if encoding fails.
- **Displays and scaling**
  - Both executables now run with per-monitor v2 DPI awareness. v1.0.0
    declared the older per-monitor mode in its manifest, so the shipped
    application ran in a different DPI mode than the one its tests exercised.
  - Hiding the taskbar or docking an app bar no longer discards a screenshot
    that is being edited.
  - A maximized or minimized trim window is no longer resized when the display
    configuration changes.
  - Selection handles are as easy to grab at 200 % as at 100 %.
- **Other**
  - Right-clicking the tray icon can no longer open a second menu inside the first.
  - The portable instructions named the wrong shortcut; it is Ctrl+Shift+A.

## Performance

- Recording reuses its GPU read-back texture instead of creating one per frame.
- The cursor is drawn through a cursor-sized surface and skipped when it is
  outside the recorded region; previously the whole frame was copied twice per
  frame whenever a cursor was shown.
- The idle trim timeline is no longer repainted ten times a second.

## Security

- Library loading is restricted to the Windows system directory. A DLL placed
  beside the portable executables is no longer loaded.
- Cleanup of temporary recordings verifies that every entry it deletes still
  resolves inside the directory it was listed in, closing a junction race.
- Binaries are built with CET shadow-stack compatibility and high-entropy ASLR
  in addition to Control Flow Guard and DEP.
- The preview helper's diagnostics can no longer corrupt its protocol stream,
  and the application range-checks what the helper reports.
- Release packages carry a build provenance attestation, and the build
  workflow pins third-party actions to commits.

No vulnerability in v1.0.0 is known to have been exploited. These changes
reduce exposure; they are not a response to a report.

| **[Easnap-v1.0.1-windows-x64-setup.exe](https://github.com/vseprr/easnap/releases/download/v1.0.1/Easnap-v1.0.1-windows-x64-setup.exe)** | Installer. Installs for the current user without administrator rights, adds a Start menu entry and an uninstaller. |
| **[Easnap-v1.0.1-windows-x64.zip](https://github.com/vseprr/easnap/releases/download/v1.0.1/Easnap-v1.0.1-windows-x64.zip)** | Portable copy: extract everything and run `bin\Easnap.exe`. |
| `*.sha256` | SHA-256 checksum for each package |

Both packages contain the same two executables. Easnap targets Windows 10 and
Windows 11, x64. The binaries and the installer are **unsigned**, so Windows
may display a publisher or reputation warning.

To check a download:

```powershell
Get-FileHash .\Easnap-v1.0.1-windows-x64-setup.exe -Algorithm SHA256
gh attestation verify .\Easnap-v1.0.1-windows-x64-setup.exe --repo vseprr/easnap
```

Exit Easnap before installing over, or replacing, an existing copy. Settings
and temporary recordings stay in `%LOCALAPPDATA%\Easnap` and are not removed
by the uninstaller.

## Validation

Tested on one development PC: Windows 10, two 1920x1080 displays at 125 %.

- The Release x64 build succeeded with warnings as errors. Both executables
  report 1.0.1.0.
- All 39 registered automated tests passed on the final binaries, but not in a
  single run. In the complete run 37 passed; `trim_timeline_seek_soak` failed
  because the real pointer was moved while the test used it, and
  `annotation_editing_native`, which is intermittent, failed. Both passed in
  the following rerun. `annotation_editing_native` remains unstable.
- The installer was installed silently, the installed application was started,
  and it was uninstalled cleanly, on that same PC only.
- Losing an audio device and changing or disconnecting a display during use
  were not exercised on hardware. Those fixes rest on code review and on
  automated layout tests.
- No scale factor other than 125 %, no mixed-DPI layout and no other Windows
  version, GPU or audio device was used.

Details, including unsuccessful runs, are in
[project status](https://github.com/vseprr/easnap/blob/v1.0.1/docs/project-status.md).

## Known issues and limits

- **Trim resizing:** transient redraw artifacts can still occur while resizing
  or maximizing the Trim window. This is unchanged from v1.0.0.
- **Blur and Pixelate while dragging:** previewing or moving a large effect on
  a 4K screenshot recomputes the whole image on every pointer move and can lag.
- **Compatibility coverage:** physical testing covers two 1920x1080 displays
  at 125 %. Layout at other sizes and scale factors is covered by automated
  layout tests only. Other GPUs, audio devices, mixed-DPI layouts, HDR displays
  and accessibility tools have not been checked on real hardware.
- **Very large recording regions:** a region beyond the H.264 encoder's limits
  (for example across two 4K displays) fails to start with a general message.
- **GIF preview:** the preview plays the source recording. GIF palette and
  frame-rate conversion happen during export.
- **MP4 trimming:** cut points follow video/audio sample granularity. Late
  excerpts from long recordings can take longer because decoding starts at the
  source beginning.
