# Easnap v1.1.0-rc.1

The release candidate of v1.1. Unless testing finds a problem, v1.1.0 is this
version under its final number. It makes Easnap say only what is true when a
recording cannot be opened or saved, keeps more of its own windows out of
pictures without leaving black boxes, and keeps crash reports from replacing
each other.

This is a prerelease. The latest stable version is v1.0.2. A release candidate
installs over a stable version or a beta and uses the same settings; to go
back, install v1.0.2 again.

## Fixed

- **Messages about an unsaved recording.** When the trim window could not
  open, Easnap said it would offer the recording at the next start. That
  depends on a marker file; if writing it failed, the recording was deleted at
  the next start instead. Easnap now tries again, and if it still cannot, it
  says that the recording is kept only until Easnap starts again and shows
  where it is, so that you can copy it.
- **Saving a recording without a preview** to a place where it could not be
  written promised an offer at the next start. The recording is still open at
  that moment, so the message now asks you to choose another place.
- **Black boxes from dialogs and lists.** Help during a Scrollshot, the Exit
  question during a recording, Settings, the font-size list and the text box
  of the editor could leave a black box in a picture when they were shown
  again or moved, as the islands could before v1.1.0-beta.2.
- **The mode island under a top taskbar.** With the taskbar at the top of the
  screen, the Screenshot/Scrollshot/Record island was partly under it. It now
  starts below the taskbar.
- **Text cut off at 150 % scale.** The status message of a Scrollshot and the
  value labels of the editor's options (for example "Boyut 96 pt") were cut
  off when Windows scales the display to 150 %. They now take the room their
  text needs.
- **Crash reports.** A crash report could replace an earlier one written in
  the same second. Every report now keeps its own file.

## Changed

- From v1.1.0 on, **Check for updates** opens the latest stable release. A
  prerelease such as this one still opens the list of all releases.

Both packages contain the same two executables. Easnap needs Windows 10
version 2004 or later, x64. The binaries and the installer are **unsigned**,
so Windows may display a publisher or reputation warning; on Windows 11 with
Smart App Control turned on, Windows can block them.

To check a download:

```powershell
Get-FileHash .\Easnap-v1.1.0-rc.1-windows-x64-setup.exe -Algorithm SHA256
gh attestation verify .\Easnap-v1.1.0-rc.1-windows-x64-setup.exe --repo vseprr/easnap
```

Exit Easnap before installing over, or replacing, an existing copy.

## Validation

- In the test lab, a virtual machine with Windows 10 22H2 and no GPU, every
  test passed on the final sources with no retry: all 54, including the long
  repeats, at 125 % display scale, and the 48 of the Full set in a second
  image at 150 %. One recording test used its fallback capture, as it does
  on a still desktop.
- The image at 150 % is new with this version. Its first runs found the
  cut-off texts listed above and two tests that assumed 125 %; the tests
  were corrected.
- An upgrade from v1.0.2 in the lab: the v1.0.2 installer, then this one,
  both silent. Windows then listed one Easnap, version 1.1.0-rc.1, and the
  settings file was unchanged.
- The lab cannot check the installer's pages, Start with Windows, Scrollshot
  on real applications or how the Turkish text reads; those are left to a
  check by hand. The [validation records](validation-history.md#validation-of-v110-rc1)
  list every run, and [project status](../project-status.md#not-validated)
  what has not been checked.

## Known issues

- On GitHub's test machines, which have no GPU, a trim export of a recording
  with audio failed now and then; the cause is being investigated. If an
  export fails, try it again.
- Scrollshot follows content that moves only when you scroll. Video,
  animations or a list that loads more while it scrolls inside the frame can
  make it lose track; narrow the frame.
- Copying and saving a very tall image take a moment during which the island
  does not respond.
- A screenshot can differ from the screen by one level at a few colour values
  while the workspace is visible. Scrollshot is not affected.
- Transient redraw artifacts can occur while resizing or maximizing the Trim
  window.

and [troubleshooting](../troubleshooting.md) for the questions that come up
