# Easnap v1.2.0

v1.2 adds **Pin to screen**: a finished screenshot can stay on top of your
other windows as a small picture you can move, zoom, copy and save. It also
makes recording, copying and the editor sturdier. These notes cover
everything that changed since v1.1.0.

## New

- **Pin to screen.** In the screenshot tools, the new pin button or **Ctrl+T**
  keeps the finished image, with its annotations, on top of other windows and
  closes the capture.
  - A screenshot appears exactly where it was taken, at its real size, with a
    thin border that takes the accent colour while the pin is active.
  - **Drag** a pin anywhere to move it. The **wheel** zooms it between 10 %
    and 400 % around the pointer; **Ctrl+1** returns to the real size.
  - **Ctrl+C** copies the pinned image and **Ctrl+S** saves it, the same way
    as from the editor, including saving straight into your screenshots
    folder when Settings say so.
  - **Double-click** or **Esc** closes a pin. A right-click opens a menu with
    Copy, Save..., Original size, Close, and Close all pinned images when more
    than one is open.
  - Any number of pins can be open; the newest is on top. A stitched
    Scrollshot image that you are editing can be pinned too; it starts reduced
    to fit the screen.
  - Pins are part of what is on your screen: later screenshots, Scrollshots
    and recordings contain them. Move or close a pin first to keep it out.
  - Exit closes every pin, without asking. Pins are not restored at the next
    start.

## Changed

- **Undo** goes back up to 200 steps. Older steps are dropped, so a long
  editing session no longer uses more and more memory.
- **Copying a very tall image** no longer keeps other applications from the
  clipboard while Easnap prepares it.
- The screenshot tools island is one button wider. On a narrow screen its
  buttons wrap onto a second row, as before.

## Fixed

- If Windows ran out of memory or threads while a recording captured audio,
  Easnap could close and the recording was lost. Easnap now ends the
  recording's audio as failed and keeps running.

## Under the hood

- The capture coordinator keeps the session state in one small state machine,
  the first step of splitting it into parts
  ([ADR-039](../decisions/ADR-039-coordinator-trim-flow.md)).
- The static analysis that GitHub runs on every change now fails on any
  finding instead of only reporting.

## Upgrading from v1.1.0

- v1.2.0 installs over v1.1.0 as the same program and keeps its settings.
  Exit Easnap before you install.
- Nothing in the settings file changes.

Both packages contain the same two executables. Easnap needs Windows 10
version 2004 or later, x64. The binaries and the installer are **unsigned**,
so Windows may display a publisher or reputation warning; on Windows 11 with
Smart App Control turned on, Windows can block them.

To check a download:

```powershell
Get-FileHash .\Easnap-v1.2.0-windows-x64-setup.exe -Algorithm SHA256
gh attestation verify .\Easnap-v1.2.0-windows-x64-setup.exe --repo vseprr/easnap
```

Exit Easnap before installing over, or replacing, an existing copy.

## Validation

- **In the test lab,** virtual machines with Windows 10 22H2 and no GPU: the
  Full set (50 tests) after every change and the long repeats (56 tests) after
  the last ones, at 125 % display scale; on the sources of this version all 56
  at 125 % and the 50 of the Full set in a second image at 150 %. In the first
  run at 150 % one timing check of the recording test failed: on its fallback
  capture it took 84 of 90 frames while tests ran in parallel. The runner's
  retry and the repeated run passed; v1.2 does not change that part of
  Easnap. One recording test used its fallback capture, as it does on a still
  desktop.
- **By the owner,** on the development PC with one display at 125 %: Pin to
  screen as it was built, then a release candidate that was not published,
  installed over v1.1.0 and used for a second round: pins, screenshots copied
  and saved, a recording trimmed and saved, and a Scrollshot copied. Neither
  round found a problem.
- Not checked: a pin moved between monitors of different scale, long use of
  many pins, Windows 11 and an N edition. The
  [validation records](validation-history.md#validation-of-v120) list the
  runs, and [project status](../project-status.md#not-validated) what has not
  been checked.

## Known issues

- Pins are captured like any other window; there is no option yet to keep
  them out of screenshots and recordings.
- Copying and saving a very tall image still take a moment during which the
  island does not respond.
- A screenshot can differ from the screen by one level at a few colour values
  while the workspace is visible. Scrollshot is not affected.
- Transient redraw artifacts can occur while resizing or maximizing the Trim
  window.

See [troubleshooting](../troubleshooting.md) for the questions that come up
most often.
